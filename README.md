# ОргКонтур — анализ организационной структуры и функций

Рабочий MVP на React + FastAPI для сравнения документов «до» и «после» реорганизации. Проект объединяет React-интерфейс и аналитический конвейер из второго прототипа.

## Возможности

- Загрузка нескольких TXT, DOCX, XLSX и PDF с текстовым слоем с обеих сторон.
- Извлечение пунктов, ролей, подразделений и функций с указанием источника.
- Сравнение структуры и функций, поиск возможной потери, дублей и самопроверки.
- История проектов, подтверждение/отклонение выводов с комментарием.
- Заключение и экспорт DOCX, Markdown, CSV и JSON.
- Режим по правилам без ключа; готовый режим OpenAI после настройки ключа.

Выводы рекомендательные. Отсутствие найденного соответствия не доказывает исчезновение функции из компании.

## Запуск

Нужны Python 3.11+ и Node.js 20+. Откройте два терминала в корне репозитория.

Терминал 1:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
backend/.venv/bin/uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Терминал 2:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:3000`. API: `http://127.0.0.1:8000/docs`. Если зависимости уже установлены, повторять установку не нужно. По умолчанию проекты хранятся в памяти и исчезают после перезапуска API.

## Проверка

1. Нажмите «Контрольный пример», затем «Начать анализ» в режиме «По правилам, без ИИ».
2. Проверьте потерю реестра страховых договоров, дубль проверки расходов между двумя отделами и риск самопроверки договоров закупок.
3. Откройте источник, подтвердите или отклоните вывод и скачайте Word или CSV.
4. Нажмите «Пример №8 → №9»: должны сохраниться ДНМ и ДККМ и появиться ДИТААД и ДОА.

Контрольные документы находятся в `data/samples/`. Проверки разработчика:

```bash
backend/.venv/bin/python -m pytest -q backend/tests
cd frontend && npm run build
```

## Как подключить ИИ

Скопируйте корневой `.env.example` в `.env`, заполните `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL`, затем перезапустите API. В интерфейсе станет доступен режим OpenAI. Ключ хранится на сервере; при выборе ИИ текст документов передаётся провайдеру.

`backend/app/provider.py` содержит типизированные вызовы OpenAI Responses API. `backend/app/pipeline.py` и `evidence.py` проверяют полноту сопоставления и точность цитат. Живую работу модели необходимо отдельно проверить после добавления ключа.

Для постоянного хранения задайте `KONTUR_STORAGE=mongodb` и `MONGODB_URI` в корневом `.env`. Для локального демо оставьте `memory`.

## Архитектура

| Часть | Назначение |
|---|---|
| `frontend/src/App.tsx` | Загрузка, история, результаты, решения и экспорт |
| `backend/app/parsers.py` | Адресованные фрагменты TXT/DOCX/XLSX/PDF |
| `backend/app/baseline.py` | Проверка по правилам без ключа |
| `backend/app/provider.py` | Смысловой анализ через OpenAI |
| `backend/app/evidence.py` | Проверка источника и дословной цитаты |
| `backend/app/pipeline.py` | Извлечение, сопоставление, риски, заключение |
| `backend/app/memory_storage.py`, `storage.py` | Память или MongoDB/GridFS |

Подробнее: `docs/architecture.md`.

## Границы MVP

- Без ИИ сильная переформулировка функций может давать ложные совпадения или потери.
- Сканам PDF нужен OCR; старые DOC/XLS требуется пересохранить в DOCX/XLSX.
- Проверка внешних норм и сравнение с другими операторами ждут соответствующие источники.
- Авторизации пока нет: использовать локально или в закрытом контуре.
