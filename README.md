# ОргКонтур

**ИИ-помощник для анализа организационной структуры и функций при реорганизации.** Проект для хакатона, трек «Казахтелеком».

ОргКонтур сравнивает два комплекта организационных документов — «до» и «после» изменений. Он помогает аналитикам, специалистам по организационному развитию и внутреннему контролю понять, кому переданы обязанности, какие функции изменились и где могли возникнуть пробелы, дублирование или конфликт интересов.

Результат — сопоставление функций и подразделений, выводы с цитатами из документов и заключение для проверки человеком. Выводы рекомендательные: отсутствие соответствия в загруженных документах не доказывает исчезновение функции из компании.

## Что реализовано

- Загрузка нескольких TXT, DOCX, XLSX и PDF с текстовым слоем с обеих сторон.
- Извлечение пунктов, ролей, подразделений и функций с указанием источника; отдельный реестр «подразделение → функция → пункт».
- Карта судьбы функций «до → после», сравнение структуры, поиск возможной потери, дублей и самопроверки.
- Для спорного сопоставления — «Недостаточно данных»; для возможной потери — область поиска и ближайшие формулировки для проверки.
- Экран проверки доказательств: цитаты двух редакций рядом. Сервер проверяет существование пункта и совпадение цитаты, но не утверждает, что смысловой вывод доказан.
- История проектов, подтверждение/отклонение выводов с комментарием.
- Заключение и экспорт DOCX, Markdown, CSV и JSON.
- Смысловой ИИ-анализ через OpenAI с проверкой источников на сервере.

Выводы рекомендательные. Отсутствие найденного соответствия не доказывает исчезновение функции из компании.

## Установка и запуск

### Требования

- Python 3.11+ как рекомендуемая среда запуска.
- Node.js **20.19+ в ветке 20 либо 22.12+** — согласно требованиям установленного Vite; npm.
- Для смыслового анализа — ключ OpenAI и интернет. Для локального режима `baseline` ключ не нужен.
- Свободные порты `3000` и `8000`.

### 1. Получить проект

```bash
git clone https://github.com/BAITC-Hacks/hack-528e4c67-sixsevensquad.git
cd hack-528e4c67-sixsevensquad
```

### 2. Установить зависимости

**Windows, PowerShell:**

```powershell
python -m venv backend/.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm --prefix frontend ci
```

**Linux / macOS:**

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
```

Команды выполняются из корня репозитория. `npm install` в корне не устанавливает зависимости интерфейса — они находятся в `frontend/`.

### 3. Настроить окружение

Создайте файл `.env` **в корне репозитория** и заполните его. Если файл уже есть, сохраните существующие настройки. В текущем репозитории `.env.example` пустой; используйте шаблон ниже:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI
OPENAI_MODEL=gpt-4.1-mini
KONTUR_STORAGE=memory
KONTUR_MAX_CHARS=250000
KONTUR_MAX_CALLS=80
```

Для проверки только через `baseline` строку `OPENAI_API_KEY` можно не задавать. Ключ читает backend; помещать его в переменные `VITE_*` не нужно. `.env` исключён из Git.

Постоянное хранение включается дополнительно:

```dotenv
KONTUR_STORAGE=mongodb
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DATABASE=kontur
```

MongoDB должна быть запущена и доступна отдельно. При использовании облачного кластера укажите его URI и настройте сетевой доступ. После изменения `.env` перезапустите API.

### 4. Запустить сервер и интерфейс

В первом терминале, из корня репозитория:

**Windows:**

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

**Linux / macOS:**

```bash
backend/.venv/bin/python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Во втором терминале, также из корня:

```bash
npm --prefix frontend run dev -- --host 127.0.0.1 --strictPort
```

Откройте [ОргКонтур](http://127.0.0.1:3000). Проверка API: [health](http://127.0.0.1:8000/api/health).

На Linux/macOS вместо двух команд запуска можно использовать `bash dev.sh`: скрипт рассчитан на окружение `backend/.venv/bin/` и уже установленные зависимости.

### Сборка интерфейса

```bash
npm --prefix frontend run build
npm --prefix frontend run preview -- --host 127.0.0.1 --port 4173
```

Сборка появится в `frontend/dist/`, локальный просмотр — на `http://127.0.0.1:4173`. Backend должен работать отдельно. `preview` предназначен для проверки сборки; для публичного размещения потребуется настроить раздачу файлов и маршрутизацию `/api` к backend.

## Как проверить решение жюри

### Сценарий с OpenAI

1. Запустите приложение с заполненным `OPENAI_API_KEY`.
2. В разделе «Документы» нажмите **«Контрольный пример»**, затем **«Начать анализ»**.
3. Дождитесь завершения. Изучите «Результаты анализа», «Структура» и «Сравнение функций».
4. Сверьте выводы с контрольными ситуациями в `data/samples/expected.json`: преобразование отдела финансового контроля, отсутствие соответствия для реестра страховых договоров, возможный дубль проверки расходов и самопроверка договоров закупок. Это **ожидания для проверки**, а не обещание конкретного ответа модели.
5. В разделе «Риски» откройте вывод и его источники. Сравните цитаты «до» и «после», сохраните решение и комментарий.
6. Откройте «Заключение» и скачайте DOCX или CSV. Проверьте сохранённое решение в результатах.
7. Откройте проект через «Историю проектов». Дополнительно повторите анализ для **«Пример №8 → №9»** или загрузите свои файлы.

### Проверка без ключа OpenAI

Серверный режим `baseline` позволяет проверить весь путь от документов до экспорта без расходов на внешний API:

1. Откройте `http://127.0.0.1:8000/docs`.
2. Выполните `POST /api/projects/sample` с `kind=control`, скопируйте `id` из ответа.
3. Выполните `POST /api/projects/{pid}/analyze`, указав этот ID и тело `{"mode":"baseline"}`.
4. Проверяйте `GET /api/projects/{pid}` до статуса `completed`; при `failed` посмотрите поле `error`.
5. Откройте `http://127.0.0.1:3000/?project=ID_ПРОЕКТА&view=overview`, подставив полученный ID. Проверьте источники, сохранение решений и экспорт в интерфейсе.

Этот сценарий проверяет механику приложения и лексические правила. Он не подтверждает качество работы OpenAI. Кнопка «Начать анализ» в интерфейсе использует именно OpenAI.

### Автоматические проверки

Тестовые зависимости устанавливаются отдельно: `pytest` не входит в `backend/requirements.txt`; для TestClient требуется `httpx`.

**Windows:**

```powershell
.\backend\.venv\Scripts\python.exe -m pip install pytest httpx
.\backend\.venv\Scripts\python.exe -m pytest -q backend/tests
npm --prefix frontend run build
```

**Linux / macOS:**

```bash
backend/.venv/bin/python -m pytest -q backend/tests
npm --prefix frontend run build
```

## Настройки OpenAI

Для новой установки скопируйте корневой `.env.example` в `.env`, заполните `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL`, затем перезапустите API. Если `.env` уже настроен, сохраните его. Сайт запускает анализ через OpenAI; ключ хранится на сервере, текст документов передаётся провайдеру.

`backend/app/provider.py` содержит типизированные вызовы OpenAI Responses API. `backend/app/pipeline.py` и `evidence.py` проверяют полноту сопоставления и точность цитат. Контрольный комплект позволяет проверить качество ответа подключённой модели.

ИИ получает фрагменты документов партиями. При сопоставлении ему передаётся компактный каталог функций с идентификаторами, владельцами, действиями, объектами и областями ответственности; полные цитаты остаются на сервере для независимой проверки. Запросы отправляются с `store=False`. Модель может вернуть «Недостаточно данных», а не принудительно объявлять функцию потерянной. Тесты проверяют контракт ИИ-адаптера без обращения к внешнему API. Доступность выбранной модели и качество реального анализа зависят от вашего ключа и проверяются отдельным прогоном.

Для постоянного хранения задайте `KONTUR_STORAGE=mongodb` и `MONGODB_URI` в корневом `.env`. Для локального демо оставьте `memory`.

## Архитектура

| Часть | Назначение |
|---|---|
| `frontend/src/App.tsx` | Загрузка, история, результаты, решения и экспорт |
| `backend/app/parsers.py` | Адресованные фрагменты TXT/DOCX/XLSX/PDF |
| `backend/app/baseline.py` | Лексический провайдер для автоматических тестов |
| `backend/app/provider.py` | Смысловой анализ через OpenAI |
| `backend/app/evidence.py` | Проверка источника и дословной цитаты |
| `backend/app/pipeline.py` | Извлечение, сопоставление, риски, заключение |
| `backend/app/memory_storage.py`, `storage.py` | Память или MongoDB/GridFS |

Подробнее: `docs/architecture.md`.

## Границы MVP

- Проверка цитат подтверждает наличие текста, но не истинность интерпретации; все риски и потери требуют решения аналитика.
- Сканам PDF нужен OCR; старые DOC/XLS требуется пересохранить в DOCX/XLSX.
- Проверка внешних норм и сравнение с другими операторами ждут соответствующие источники.
- Авторизации пока нет: использовать локально или в закрытом контуре.
