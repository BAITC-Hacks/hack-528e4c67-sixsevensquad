# ОргКонтур — анализ организационной структуры и функций

Рабочий MVP на React + FastAPI для сравнения документов «до» и «после» реорганизации. Проект объединяет React-интерфейс и аналитический конвейер из второго прототипа.

## Возможности

- Загрузка нескольких TXT, DOCX, XLSX и PDF с текстовым слоем с обеих сторон.
- Извлечение пунктов, ролей, подразделений и функций с указанием источника; отдельный реестр «подразделение → функция → пункт».
- Карта судьбы функций «до → после», сравнение структуры, поиск возможной потери, дублей и самопроверки.
- Для спорного сопоставления — «Недостаточно данных»; для возможной потери — область поиска и ближайшие формулировки для проверки.
- Экран проверки доказательств: цитаты двух редакций рядом. Сервер проверяет существование пункта и совпадение цитаты, но не утверждает, что смысловой вывод доказан.
- История проектов, подтверждение/отклонение выводов с комментарием.
- Заключение и экспорт DOCX, Markdown, CSV и JSON.
- Смысловой ИИ-анализ через OpenAI с проверкой источников на сервере.
- Продолжение после сбоя с сохранёнными ответами, остановка анализа, счётчики запросов/времени/расходов.
- История с поиском и статусами, постраничные результаты, предупреждения о неполном извлечении.

Выводы рекомендательные. Отсутствие найденного соответствия не доказывает исчезновение функции из компании.

## Запуск

Нужны Python 3.11+ и Node.js 20+. Первый раз установите зависимости в корне репозитория:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
cd frontend && npm ci && cd ..
```

Затем запуск одной командой из корня:

```bash
bash dev.sh
```

Откройте `http://127.0.0.1:3000`. API: `http://127.0.0.1:8000/docs`. Если зависимости уже установлены, повторять установку не нужно. Порты 8000 и 3000 должны быть свободны. По умолчанию проекты хранятся в памяти и исчезают после перезапуска API.

## Проверка

1. Нажмите «Контрольный пример», затем «Начать анализ». Сайт автоматически использует OpenAI.
2. Проверьте вероятное преобразование отдела финансового контроля в два новых отдела, потерю реестра страховых договоров, дубль проверки расходов и риск самопроверки договоров закупок.
3. В «Карте функций» откройте «Доказательства», сравните пункты двух редакций, подтвердите или отклоните вывод и скачайте Word или CSV.
4. Нажмите «Пример №8 → №9»: должны сохраниться ДНМ и ДККМ и появиться ДИТААД и ДОА.

Контрольные документы находятся в `data/samples/`. Проверки разработчика:

```bash
backend/.venv/bin/pip install -r backend/requirements-dev.txt
backend/.venv/bin/python -m pytest -q backend/tests
cd frontend && npm run build
```

## Настройки OpenAI

Для новой установки скопируйте корневой `.env.example` в `.env`, заполните `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL`, затем перезапустите API. Если `.env` уже настроен, сохраните его. Сайт запускает анализ через OpenAI; ключ хранится на сервере, текст документов передаётся провайдеру.

`backend/app/provider.py` содержит типизированные вызовы OpenAI Responses API. `backend/app/pipeline.py` и `evidence.py` проверяют полноту сопоставления и точность цитат. Контрольный комплект позволяет проверить качество ответа подключённой модели.

ИИ получает фрагменты документов партиями. При сопоставлении ему передаётся компактный каталог функций с идентификаторами, владельцами, действиями, объектами и областями ответственности. При проверке рисков дополнительно передаются цитаты текущей партии, чтобы не потерять ограничения и независимость проверки. Источники проверяются на сервере. Запросы отправляются с `store=False`. Модель может вернуть «Недостаточно данных», а не принудительно объявлять функцию потерянной. Тесты проверяют контракт ИИ-адаптера без обращения к внешнему API. Доступность выбранной модели и качество реального анализа зависят от вашего ключа и проверяются отдельным прогоном.

Для постоянного хранения задайте `KONTUR_STORAGE=mongodb` и `MONGODB_URI` в корневом `.env`. Для локального демо оставьте `memory`.

Альтернатива Atlas: `KONTUR_STORAGE=local` сохраняет проекты в `runtime/projects` на этом компьютере. Это явный режим, а не автоматическая подмена недоступной MongoDB. `runtime/` исключён из Git. Данные из старого режима `memory` автоматически в Atlas не переносятся.

### Остановка и продолжение

При сбое или остановке откройте тот же проект в истории и нажмите «Продолжить анализ». Уже завершённые запросы берутся из кэша проекта. Счётчик запросов и расходов не сбрасывается. Новый проект имеет отдельный кэш и бюджет. В `memory` кэш исчезает при перезапуске; в MongoDB и `local` сохраняется.

`dev.sh` запускает один процесс API без автоматической перезагрузки: изменение кода не должно обрывать платный анализ. После изменения `.env` или backend перезапустите сервер вручную. Одновременно выполняется один проект; извлечение внутри него использует два параллельных запроса. Не запускайте несколько процессов API с одной базой: восстановление заданий рассчитано на один процесс.

| Настройка | По умолчанию | Что ограничивает |
|---|---|---|
| `KONTUR_BUDGET_USD` | `0.50` | Расчётные расходы проекта с резервом на незавершённые запросы |
| `KONTUR_MAX_CALLS` | `80` | Число запросов проекта, включая повторные попытки |
| `KONTUR_REQUEST_TIMEOUT` | `75` | Секунды ожидания одного запроса |
| `KONTUR_ANALYSIS_SECONDS` | `600` | Секунды одной попытки анализа |
| `KONTUR_MAX_OUTPUT_TOKENS` | `6000` | Лимит ответа; слишком большие части делятся повторно |

Остановка не отменяет уже отправленный запрос у провайдера: она запрещает следующие запросы и сохраняет завершённые ответы. Расходы приблизительные и не заменяют биллинг OpenAI; неизвестная стоимость неудачных запросов остаётся в резерве. Расчёт настроен для `gpt-4.1-mini` и `gpt-4.1-mini-2025-04-14`; другие модели требуют отдельной настройки тарифов.

### Живая проверка, не имитация ИИ

Эти команды отправляют документы OpenAI и расходуют API-бюджет:

```bash
# Контрольный комплект: до $0.03; результат и кэш — runtime/live-control.
backend/.venv/bin/python scripts/live_smoke.py --control
# Сквозной API/OpenAI/Atlas: загрузка, результат, четыре экспорта, повторное чтение.
backend/.venv/bin/python scripts/verify_integration.py
# Собственные документы, явно заданный бюджет:
backend/.venv/bin/python scripts/verify_integration.py --before before.pdf --after after.pdf --budget 0.50
# Продолжить тот же незавершённый проект без потери кэша:
backend/.venv/bin/python scripts/verify_integration.py --project-id PROJECT_ID --budget 0.50
```

Проверка Atlas оставляет созданный проект в истории; она не удаляет данные и не перезапускает существующие задания. Если анализ уже выполняется, проверка не стартует. Не выдавайте прохождение автоматических тестов с подменой провайдера за проверку качества настоящей модели.

Матрица требований: [docs/requirements.md](docs/requirements.md). Проверки объединённой версии: [docs/verification.md](docs/verification.md).

Для передачи исходников: `backend/.venv/bin/python scripts/package_project.py`. Архив появится в `runtime/release/`; `.env`, данные проектов и зависимости не включаются. Если в `.env.example` заполнены ключ или URI, упаковка остановится.

Отдельный необязательный браузерный тест: остановите обычный API, запустите `backend/.venv/bin/python -m uvicorn backend.tests.browser_server:app --host 127.0.0.1 --port 8000`, отдельно frontend, затем `backend/.venv/bin/python -m playwright install chromium` и `backend/.venv/bin/python scripts/browser_smoke.py`. Этот тест использует синтетический провайдер и не доказывает качество OpenAI. Не запускайте его против обычного приложения: оно делает платные запросы.

## Архитектура

| Часть | Назначение |
|---|---|
| `frontend/src/App.tsx` | Загрузка, история, результаты, решения и экспорт |
| `backend/app/parsers.py` | Адресованные фрагменты TXT/DOCX/XLSX/PDF |
| `backend/app/baseline.py` | Лексический провайдер для автоматических тестов |
| `backend/app/provider.py` | Смысловой анализ через OpenAI |
| `backend/app/evidence.py` | Проверка источника и дословной цитаты |
| `backend/app/pipeline.py` | Извлечение, сопоставление, риски, заключение |
| `backend/app/memory_storage.py`, `storage.py` | Память или MongoDB/GridFS |

Подробнее: `docs/architecture.md`.

## Границы MVP

- Проверка цитат подтверждает наличие текста, но не истинность интерпретации; все риски и потери требуют решения аналитика.
- Сканам PDF нужен OCR; старые DOC/XLS требуется пересохранить в DOCX/XLSX.
- Проверка внешних норм и сравнение с другими операторами ждут соответствующие источники.
- Авторизации пока нет: использовать локально или в закрытом контуре.
