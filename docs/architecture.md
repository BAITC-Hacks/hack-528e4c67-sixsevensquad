# Архитектура и качество выводов

```
React → FastAPI → парсеры → адресованные фрагменты → OpenAI
      → проверка источников → проект и заключение → решение аналитика → экспорт
```

Каждый файл разбивается на фрагменты `Clause`: имя документа, сторона «до/после», пункт и адрес строки, таблицы или страницы, дословный текст. Функция хранит владельца, действие, объект, область и доказательство `Evidence`. Каждая старая функция сравнивается со всем новым каталогом; новые функции без прежнего соответствия выделяются отдельно. Если соответствие нельзя убедительно установить, ставится `uncertain`, а не «потеря».

Сервер отклоняет ссылку на несуществующий фрагмент, цитату не из документа, функцию/подразделение без цитаты из обрабатываемой части и неполный список сопоставлений. Для вывода о передаче нужны источники обеих редакций, а для потенциальной потери — доказательство существования функции «до» и журнал области поиска «после». Последний не доказывает отсутствия функции во всей организации. Ближайшие по словам кандидаты показываются только как подсказка аналитику. Решения аналитика сохраняются отдельно и включаются в заключение.

ИИ-адаптер использует структурированный ответ по Pydantic-схеме через Responses API. На этапе сопоставления и проверки рисков цитаты не посылаются повторно: модель получает компактные записи и ID. Исходные цитаты присоединяются к выводу и проверяются после ответа. Для каждого вывода отображается «проверена ссылка/цитата» отдельно от «смысл требует проверки». Контракт проверяется имитацией ответа в автоматических тестах; для оценки качества подключённой модели используется контрольный комплект. Лексический провайдер сохранён для тестов; интерфейс запускает OpenAI.

Для точного поиска дублей нужны поля: владелец, действие, объект, процесс, зона ответственности, роль (исполняет, утверждает, контролирует, проверяет), ограничения и версия документа. Дубль — одно действие над одним объектом в одной зоне у разных владельцев без разделения ролей. Самопроверка — один владелец исполняет или утверждает и независимо проверяет тот же объект. Лексический режим отмечает кандидатов; окончательное решение за человеком.

Для сканов потребуется OCR с координатами. Для внешних требований нужен отдельный корпус актуальных норм. Для сравнения с другими операторами нужны доступные и сопоставимые структуры. Эти возможности не включены в текущий MVP.

PDF: переносы строк, включая выдачу одного слова на строку, объединяются в связные блоки по нумерации и спискам. Страница и диапазон исходных строк сохраняются; нормализуются только пробелы. При ошибке цитирования выполняется один дополнительный запрос на исправление текущей части, затем повторяется строгая проверка. Неподтверждённый ответ не публикуется. После изменения парсера комплект нужно загрузить как новый проект.
