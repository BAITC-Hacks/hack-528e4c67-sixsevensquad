# Архитектура и качество выводов

```
React → FastAPI → парсеры → адресованные фрагменты → OpenAI
      → проверка источников → проект и заключение → решение аналитика → экспорт
```

Каждый файл разбивается на фрагменты `Clause`: имя документа, сторона «до/после», пункт и адрес строки, таблицы или страницы, дословный текст. Функция хранит владельца, действие, объект, область и доказательство `Evidence`. Каждая старая функция сравнивается со всем новым каталогом; новые функции без прежнего соответствия выделяются отдельно. Если соответствие нельзя убедительно установить, ставится `uncertain`, а не «потеря».

Сервер отклоняет несуществующие ссылки и пересказы вместо цитат. Допускаются различия пробелов и регистра; неверный адрес исправляется только при единственном дословном совпадении в доступных фрагментах. После одной попытки исправления неподтверждённые записи исключаются, редакция отмечается как неполная, предупреждение показывается в интерфейсе и отчёте. При неполном извлечении отсутствие соответствия не превращается в потерю/создание. Непокрытые или некорректно сопоставленные функции и подразделения получают статус «Недостаточно данных». Контекст может устанавливать владельца, но не создавать запись без источника в обрабатываемой части.

Для вывода о передаче нужны источники обеих редакций, а для потенциальной потери — доказательство существования функции «до» и область поиска «после». Последняя не доказывает отсутствия функции во всей организации. Ближайшие по словам кандидаты показываются только как подсказка аналитику. Решения аналитика сохраняются отдельно и включаются в заключение.

ИИ-адаптер использует структурированный ответ по Pydantic-схеме через Responses API. При сопоставлении функций модель получает компактные записи и ID. Для поиска рисков дополнительно передаются цитаты текущей партии: это сохраняет условия независимости проверки и ограничения. Подразделения, должности и организации сопоставляются отдельными запросами. Исходные цитаты присоединяются к выводу и проверяются после ответа. Проверенная цитата не означает доказанный смысловой вывод. Контракт проверяется имитацией ответа в автоматических тестах; качество настоящей модели — отдельным контрольным прогоном. Лексический провайдер сохранён для тестов; интерфейс запускает OpenAI.

Извлечение: партии до 8000 символов/32 фрагментов, два запроса параллельно, разделение слишком большого ответа. Хэш запроса включает модель, инструкции, тип ответа и входные данные. Кэш изолирован по проекту. MongoDB хранит метаданные в `projects`, ответы/результаты — в GridFS, указатели ответов — в `analysis_cache`. Токены, оценка расходов, резервы и попытки сохраняются в проекте. Опрос `/status` возвращает только краткое состояние; полный результат загружается после завершения. Остановка кооперативная; при перезапуске незавершённый проект доступен для продолжения. Один процесс API, один активный проект.

Документация SDK: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Расчёт стоимости: [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). Схема ограничивает форму ответа, но не гарантирует истинность анализа.

Для точного поиска дублей нужны поля: владелец, действие, объект, процесс, зона ответственности, роль (исполняет, утверждает, контролирует, проверяет), ограничения и версия документа. Дубль — одно действие над одним объектом в одной зоне у разных владельцев без разделения ролей. Самопроверка — один владелец исполняет или утверждает и независимо проверяет тот же объект. Лексический режим отмечает кандидатов; окончательное решение за человеком.

Для сканов потребуется OCR с координатами. Для внешних требований нужен отдельный корпус актуальных норм. Для сравнения с другими операторами нужны доступные и сопоставимые структуры. Эти возможности не включены в текущий MVP.

PDF: переносы строк, включая выдачу одного слова на строку, объединяются в связные блоки по нумерации и спискам. Страница и диапазон исходных строк сохраняются; нормализуются только пробелы. При ошибке цитирования выполняется один дополнительный запрос на исправление текущей части, затем повторяется строгая проверка. Неподтверждённый ответ не публикуется. После изменения парсера комплект нужно загрузить как новый проект.
