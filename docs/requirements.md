# Соответствие ТЗ

Источник требований — задание пользователя для HackAlem AI. Реализация функции не означает гарантированное качество на любых документах.

| Требование | Реализация | Граница |
|---|---|---|
| Реорганизованные, сохранённые, созданные подразделения | Извлечение реестров, сопоставление по типам, проверка покрытия, таблица структуры | Неподтверждённые связи — неопределённость, не доказанное упразднение |
| Переходы и потери функций | Действие, объект, владелец, область; сравнение с извлечённым каталогом «после» | При неполном извлечении не объявляем потерю |
| Дубли и конфликты | Совпадение обязанностей разных владельцев; самопроверка | Конфликт интересов пока ограничен механизмом самопроверки |
| Источники существенных выводов | Файл, пункт/страница/строка, дословный фрагмент обеих сторон, область поиска | Наличие цитаты не доказывает интерпретацию |
| Аналитическое заключение | Сводка, находки, рекомендации, решения сотрудника, четыре экспорта | Выводы рекомендательные |
| Рабочий прототип и воспроизводимость | React/FastAPI, README, контрольные данные, тесты, Atlas | Нужны доступный кластер и оплачиваемый ключ OpenAI |

## Ограничения

DOCX, XLSX, текстовый PDF, UTF-8/UTF-16 TXT. Старые DOC/XLS требуют пересохранения. OCR сканов, графических оргсхем, SmartArt и встроенных объектов не реализован. Перед анализом нужна проверка извлечённого текста. Проверка законодательства и бенчмаркинг других операторов не реализованы: нужны отдельные корпуса документов. Рекомендации присутствуют.

Приложение рассчитано на одного локального пользователя/закрытый контур. Авторизации нет. Не публиковать открыто: документы и платный анализ доступны через API. Только один процесс API с одной базой.

## Контрольная приёмка

1. Загрузить синтетический контрольный комплект; найти реорганизацию, потерю реестра страховых договоров, дубль проверки расходов, самопроверку закупок.
2. Проверить не только существование цитат, но и смысл каждого вывода.
3. Пройти независимые документы, включая обе реальные редакции; явно показать замечания о неполном извлечении.
4. Проверить решения аналитика, экспорт, историю после перезапуска, остановку и продолжение.
5. Воспроизвести установку по README. Результаты актуальных проверок — в `verification.md`.

Оценка жюри: работоспособность 25, техническая реализация 25, README 25, применимость 15, развитие/оригинальность 10. Это критерии, не самооценка проекта.
